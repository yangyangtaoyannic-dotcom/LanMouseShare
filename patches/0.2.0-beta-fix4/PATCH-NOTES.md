# 0.2.0-beta-fix4 补丁说明（2026-10-29）

## 本版修复的两个问题

### 1. 文件传输"只有第一次成功，之后对端粘贴是灰色的"

**现象**（用户反馈）：复制文件后只有第一次粘贴成功，之后在另一台电脑上"粘贴"一直是灰色，双向皆如此。

**根因**（依据两台机器日志逐条核对）：
- 上一版（fix3）把文件剪贴板改成"完全懒"模式：收到对端公告只登记清单、本机剪贴板刻意留空。而 Windows 资源管理器的右键"粘贴"只有在剪贴板里有文件时才可用——剪贴板是空的，菜单自然永远是灰的。
- 唯一一次成功是物理 Ctrl+V 恰好在 Idle 态被按键拦截，触发"拉取→写剪贴板→重放"链路。主控端键盘粘贴还依赖本机剪贴板此刻恰好有文件，中间复制过文本就静默失效。

**修复**：重新启用仓库里已实现的"延迟渲染虚拟剪贴板"（`VirtualClipboardEnabled=true`），并整体加固 `VirtualFileClipboard`：

| 加固项 | 说明 |
| --- | --- |
| MTA 后台托管 | 数据对象在进程级长驻 MTA 线程上创建与发布；GetData 回调跑 MTA 工作线程，拉取大文件（实测 69 秒）不再卡死界面与输入钩子 |
| 惰性 IStream | FileContents 枚举只列 TYMED_ISTREAM，粘贴进程拿到流后 Read 时才拉取远端文件；本机随后新复制时 OleFlushClipboard 只拿廉价流指针，不会把全部文件强制渲染出来（否则每次普通复制都会触发一次完整拉取） |
| HGLOBAL 兜底 | Win7 等传统调用方请求 HGLOBAL 时在粘贴那一刻现取字节，兼容两端 |
| 发布重试 | OleSetClipboard 对 CLIPBRD_E_CANT_OPEN（剪贴板被 Explorer 瞬时占用）重试 25×50ms |
| 多文件 | EnumFormatEtc 枚举 Contents 全部 lindex 0..n-1（旧实现只列第一项） |
| 并发保护 | 拉取路径加锁，防止多个应用同时粘贴时对同一文件双拉 |

**修复后行为**：对端复制文件 → 本机剪贴板立即出现文件名，右键"粘贴"、Ctrl+V、"拉取并粘贴"按钮全部可用；字节在粘贴那一刻才开始传输。Ctrl+V 拦截链路保留为快路径，与虚拟剪贴板不冲突。

### 2. 边角阻挡 A→B 生效、B→A 仍然失效

**根因**（日志实证）：返回路径（用户从被控屏推回主控屏）走的是主控端 `TrackOwnerReturnPush` 快路径——它先于对端的注入指针检测器释放控制，而该函数此前没有任何边角检查（切出路径的 `EdgeSwitchDetector.ShouldSwitch` 才有）。日志显示用户在 B 屏左上角 (0,11)、左下角 (0,1076) 推回时照样放行。

**修复**：`TrackOwnerReturnPush` 在累计推挤位移前加边角判定：复用 `EdgeSwitchDetector.IsInBlockedCorner`，在对端屏幕坐标系里用反方向（本机在对端屏幕的另一侧）判断点是否落在顶/底 80px 角带，命中则重置累计并拒绝返回。B→A 与 A→B 行为一致。

## 版本

- 产品版本：0.2.0-beta-fix4（`src/Shared.Core/BuildInfo.cs` 单一版本源）
- 安装器 SetupVersion 保持 0.2.1（升级比较依赖纯数字 Version.TryParse，不受 beta 后缀影响）

## 安装方法

**两台电脑都要更新**（A：Win10 主控、B：Win7 被控）。

推荐用安装器：
1. 在两台电脑上分别双击 `LanMouseShareSetup.exe`（需要管理员权限），按提示完成；
2. 若使用"手动覆盖"方式：先结束 Agent（托盘退出）、`net stop LanMouseShare`，备份 `C:\Program Files\LanMouseShare`，把新版 `Agent\`、`Service\` 目录覆盖进去，再 `net start LanMouseShare`、手动启动 Agent。

## 验证要点

1. A 复制文件 → B 资源管理器右键"粘贴"应立即可用（不再灰）；点击后才开始传输；反之亦然。
2. 传输大文件时本机界面应保持响应（MTA 托管生效）。
3. 勾选"边角阻挡"后：在 B 屏左上/左下角推回鼠标，不应切回 A；从 B 屏中间部位推回正常切回。
4. 剪贴板文本同步仍正常（复制文本不被文件公告打断）。
